# Terraform AWS Modules

Reusable, versioned Terraform modules for deploying containerized Next.js
applications to AWS. This repository is consumed by the `aws-shared-foundation`
repository and by the `cookiecutter-aws-nextjs-infra` application-infrastructure
template — it does not deploy anything on its own.

See [`docs/MODULE_STANDARDS.md`](docs/MODULE_STANDARDS.md) for the required
directory layout, versioning policy, module-reference convention, and CI
requirements every module in this repository must follow.

## Modules

| Module | Purpose | Status |
| --- | --- | --- |
| `terraform-state` | Private, encrypted, versioned S3 Terraform state bucket with S3 native locking | planned |
| `route53-acm` | Import-compatible Route 53 hosted zone reference + DNS-validated `us-east-1` ACM certificate | planned |
| `github-oidc` | GitHub Actions OIDC provider + least-privilege, repo/branch-scoped deployment role | planned |
| `nextjs-lambda` | ECR repository, Lambda container function (AWS Lambda Web Adapter), Function URL | planned |
| `nextjs-assets` | Private, encrypted S3 bucket for Next.js static assets | planned |
| `nextjs-cloudfront` | CloudFront distribution fronting the Lambda Function URL and S3 assets origins via OAC | planned |

Each module will be documented individually in its own `README.md` once
implemented, generated by `terraform-docs` per the standards doc above.

## Usage

Once a module is implemented and released, consumers reference it by an exact
Git tag and module subdirectory — never a floating branch or local path:

```hcl
module "nextjs_lambda" {
  source = "git::https://github.com/24dlong/terraform-modules-library.git//modules/nextjs-lambda?ref=v1.2.0"

  name_prefix = "example-app"
  # ...
}
```

## Contributing

### Initial setup

Run `make setup-lint` once after cloning to install `pre-commit`, `checkov`,
and the repository's git hooks.

### Requirements

- Contributions must conform to [Conventional Commits](https://www.conventionalcommits.org).
- Every module must include a working example under `examples/<module-name>/`
  and pass `terraform fmt`, `terraform validate`, and `checkov` (see
  `docs/MODULE_STANDARDS.md`).

### Helpful commands

- `make setup-lint` — install `pre-commit`, `checkov`, and git hooks.
- `make lint` — run all pre-commit hooks (formatting, docs, commit-msg lint,
  Terraform fmt/validate/checkov) against the full repository.

### Technologies

- **GitHub Actions** — a pull-request quality-gate workflow (fmt/validate/
  checkov) and a merge workflow that bumps the semantic version, updates
  `CHANGELOG.md`, and tags the release whenever `main` changes.
- **Terraform** — module `required_version`/provider constraints are pinned to
  compatible ranges, never exact versions (see `docs/MODULE_STANDARDS.md`).
- **Pre-commit, Commitizen & terraform-docs** — enforce formatting, commit
  message conventions, and up-to-date module documentation before commits and
  in CI.
- **Checkov** — static security/misconfiguration analysis for every module and
  example.
